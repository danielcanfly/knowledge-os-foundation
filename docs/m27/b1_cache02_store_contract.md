## Store & ABI

* Implements the signatures from `CacheStoreV1` in frozen `m27_b0_cache_contracts.py`: `lookup_candidates(request, *, limit)`, `compare_and_swap_verified(request, record, *, previous_revision)`, and `invalidate_reachability(*, tenant_id, principal_id, source_manifest_sha256, revocation_epoch)`. Candidate reads may additionally receive a test-controlled UTC instant.
* **OFF by default**: `feature_enabled=False`; zero DB I/O for disabled, `BYPASS`, ineligible non-QA and dynamic temporal request; `REFRESH` never reads a prior answer. Config/authorization preflights run before filesystem access. No shared API, Composer, CACHE-01, -03 or -04 edited.
* The caller must supply an independently trustworthy `authority_guard(request, operation)` and a **32+ byte in-memory integrity key**, neither taken from untrusted request fields. A guard's presence is a required security precondition and **not evidence** of identity/rights. Without the guard, requests deny and no I/O occurs. The test-only guard is deliberately synthetic and cannot qualify an authentic source snapshot. Never pass the test guard or test key into an actual serving app.
* Durable SQLite WAL with `synchronous=FULL`, `BEGIN IMMEDIATE`, atomic compare-and-swap based on full SHA-256 record revision, duplicate identical-write idempotence, crash rollback, private 0700 parent/0600 file, HMAC-SHA256 row integrity, hard per-record/candidate/count/page limits. Source/ACL/rights/policy/auth-context fingerprints, revocation epoch, citations and answer SHA are in the canonical HMAC-covered payload; parse/screen on every read fail closed. The SQLite primary key binds exact question text and full scope. Deleting an invalidated row removes it from the single derived ranking index because ranking reads **only** primary records.
* Query partition = SHA-256(canonical tenant + principal + authenticated context + source corpus/revision/SHA/manifest/ACL/rights/source IDs + policy/embedding/verifier/admission versions/revocation epoch + language/task/intent/obligations/negation/numerics/temporal class/answer type). Question **text excluded from the partition** only to allow candidate discovery inside an otherwise identical scope. The unique row key additionally binds exact question text. This is not global shared cache.
* **Pluggable candidate scorer** via `candidate_ranker(query, stored)`: defaults to deterministic Unicode NFKC lexical Jaccard fallback, no LLM, local embedding or vector model. An external replacement may only rank already SQL-partitioned + HMAC-validated + screened rows, must return a bounded score, and **never** admits HIT. Similar question, exact match and high lexical score all remain `PROVER_REQUIRED`, no answer released as a product response. A real vector/embedding service or Qdrant has not been installed.
* The B0 `compare_and_swap_verified` interface has **no authenticated final-write proof input**, and `qualify_final_write` is still hardcoded `WRITE_NOT_ADMITTED`. Therefore this public method intentionally returns False, **without I/O**, until CACHE05+H01 approve a real versioned admission design. Similarly public `invalidate_reachability` cannot accept an unauthenticated identity/epoch claim and currently returns 0; G04/CACHE03 must supply real revocation authority. No fake signer, simulated formal Provider or manually seeded qualified final.
* A highly constrained `_fixture_cas` / `_fixture_invalidate` seam runs the **real durable SQLite transaction** for synthetic tests only, with `fixture_only=True`, `M27_CACHE02_FIXTURE_TEST_MODE=1`, absolute SQLite file under OS temp directory and injected synthetic authority. In fixture mode it supports AUTO fixture insert, REFRESH old-answer bypass + atomic replacement, revoke epoch floor, deleted entry and restart. These seams **must not** be called by Product or used to claim true cached answer correctness.

## Fail-closed admission & revocation semantics

1. CACHE04/H02 must construct an authenticated internal request from real native Task/IdP + effective source/ACL/rights authority, never from public source/policy fields. `parse_internal_request` rejects unrecognized fields and nonauthenticated principal before I/O.
2. CACHE02 only returns raw **candidate records**, after matching the complete request source, citations, policy, tenant/principal/auth-context, lifespan and signed-integrity *shape*. The HMAC proves only the configured local process key signed the stored bytes, **not the provenance of a final verifier receipt**.
3. CACHE03 must freshly authenticate source/current rights, negation/numeric/semantic entailment and the verifier issuer for every proposed HIT. Staleness, missing metadata, malformed content, tampering, wrong tenant or wrong epoch deny, with no stale-while-revalidate. CACHE02 alone never returns a reusable answer to an HTTP caller.
4. CACHE05 must add legitimate final-write proof and real authenticated revoke-hook admission. A REFRESH final rejected or a concurrent losing CAS preserves the old record. The fixture rollback is implemented; **actual qualified production write and revoke remain HOLD**.
5. Revocation watermark and deletions live in SQLite, persistent across ordinary process restart. A full snapshot/backup restore might restore both row and watermark. The only authoritative prevention of resurrection is an independent **current external monotonic G04 epoch and source/rights check** on every read, which is not established here. No claim of backup-proof revoke or multi-node convergence.
6. Nonprod SQLite fixture bytes are **not encrypted at rest**. HMAC catches unauthorized modification but does not hide data. Live source/answer text or secrets must **never** be written into this store until authorized at-rest encryption/key rotation (KMS/DB encryption), private retention/backup rules and current source rights are established. The test corpus is synthetic. This is a known Product security gap, not an implicitly completed requirement.
7. WAL and nominal page bound are local-process safety controls, not distributed quotas or KMS; production backup and failover are unimplemented. No online embeddings were requested or used. Legacy original MG25 Qdrant deployment refusal is not touched.

Tests cover: OFF/BYPASS zero-cache-I/O, guard deny, restart in a distinct Python interpreter, read-only candidate semantics, REFRESH CAS and idempotent duplicate, OS `SIGKILL` during open SQLite write transaction with recovery, crash injection before COMMIT, concurrent CAS in **two actual child processes** yielding exactly one winner, wrong tenant/principal/authctx, 14+ source/policy/version/rights mismatches, language/intent/negation/numeric/temporal/task/obligations, lexical near match rejected as HIT, TTL expiry, payload and MAC corruption, monotonic revoke persisted through restart, oversize and record-count cap, fixture misuse/invalid status/source/answer SHA. All fixture values and test keys are synthetic.

**PASS predicate:** clean CACHE01 base, three additive files, tests passing on Python 3.11 and 3.14, real local transactional persistence, crash and race proof, scoped failclosed candidates, no shared modifications, SHA-256 source/evidence receipt with clean local Commit. Output is **PASS_SCOPED_STORE** only; subsequent CACHE03/05/H01/H02 must close independently enumerated admission, actual semantic Provider, encryption/KMS, external revocation and Product gaps. If a consumer equates these fixture tests with a real HIT, it is incorrect.
